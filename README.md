# AiSana — карта ИИ-решений вузов Казахстана

Портал для сбора и анализа проектов вузов Республики Казахстан в области
искусственного интеллекта. Вузы ведут реестр проектов, модераторы проверяют
их перед публикацией, а посетители ищут решения по отраслям и сценариям
применения.

Портал закрыт: без входа доступны только главная страница, форма обратной
связи и служебные файлы.

## Возможности

- **Реестр проектов** — карта Казахстана, реестр по вузам и регионам, карточка
  проекта с документами и паспортом ИИ-агента.
- **ИИ-поиск** — смысловой поиск по 20 отраслевым направлениям: находит проект
  по описанию задачи, а не только по совпадению слов. Пояснения к выдаче
  пишет Gemini; ключевые слова для поиска — русские и казахские.
- **Модерация** — представитель вуза создаёт черновик и отправляет его на
  проверку, администратор или редактор публикует.
- **Импорт из Excel/CSV** — массовое заполнение реестра, со сверкой существующих
  записей и отчётом об ошибках.
- **Журнал действий** — кто и что менял, с выгрузкой отчёта в XLSX.
- **Двуязычный интерфейс** — русский и казахский, включая поиск.

## Быстрый старт

### Docker / Podman

```bash
cp .env.example .env      # задайте POSTGRES_PASSWORD и ADMIN_PASSWORD
docker compose up -d --build
```

Для Podman rootless нужно один раз создать внешний том с данными БД — он
объявлен в `docker-compose.yml` как `external`:

```bash
podman volume create ai_mapkz_postgres_data
podman-compose up -d --build
```

Дальше:

- `http://localhost:3000` — портал (также доступен по IP хоста в локальной сети);
- `GET /api/health` — состояние приложения и БД.

Сервисы в `docker-compose.yml`: `db` (PostgreSQL 16, наружу не пробрасывается),
`migrate` (применяет миграции и сид), `app`, `backup` (`pg_dump` раз в сутки в
`./backups`).

Сборка не требует интернета: шрифт Inter лежит в репозитории
(`src/app/fonts/inter-var.woff2`).

### Локальная разработка

```bash
pnpm install
cp .env.example .env
pnpm exec prisma migrate deploy
pnpm db:seed
pnpm dev
```

Сид создаёт 20 регионов, 7 групп технологий и администратора. Данные вузов и
проектов он не создаёт.

Для проверки работы с данными есть отдельный демо-сид:

```bash
pnpm db:seed:demo
```

Он добавляет 5 вузов, 7 проектов (в том числе казахский и черновик на
проверку) и четыре учётки с паролем `demo12345`:

| Учётка                 | Роль             | Что проверяет                          |
| ---------------------- | ---------------- | -------------------------------------- |
| `demo-admin@demo.kz`   | ADMIN            | Полный доступ                         |
| `demo-editor@demo.kz`  | EDITOR           | Контент без управления пользователями  |
| `demo-rep@demo.kz`     | UNIVERSITY_REP   | Только проекты своего вуза            |
| `demo-viewer@demo.kz`  | VIEWER           | Просмотр без записи                   |

После сида нажмите в админке «Пересчитать направления», чтобы проекты получили
тематические направления.

## Роли и доступ

| Роль             | Права                                                    |
| ---------------- | -------------------------------------------------------- |
| `ADMIN`          | Всё, включаяя пользователей и журнал действий             |
| `EDITOR`         | Контент (вузы, проекты, слушания, импорт), без пользователей |
| `UNIVERSITY_REP` | Только проекты и файлы своего вуза; публикует модератор  |
| `VIEWER`         | Просмотр без права записи                                |

Сессия хранится в БД (httpOnly-cookie, 30 дней). Пароль администратора
задаётся переменной `ADMIN_PASSWORD`; если она не задана, сид генерирует
случайный и печатает его в лог.

## Конфигурация

Все переменные перечислены в `.env.example`.

| Переменная                | Обязательна | Назначение                                                       |
| ------------------------- | ----------- | ---------------------------------------------------------------- |
| `POSTGRES_PASSWORD`       | да          | Пароль БД. Меняется только при первичной инициализации тома       |
| `DATABASE_URL`            | для локали  | Строка подключения к БД вне Docker                               |
| `NEXT_PUBLIC_APP_URL`     | нет         | Публичный адрес: sitemap, OpenGraph, ссылки в письмах            |
| `ADMIN_PASSWORD`          | нет         | Пароль создаваемого администратора; иначе — случайный в логе сида |
| `GEMINI_API_KEY`          | нет         | Ключ Gemini для ИИ-поиска; без него поиск работает без пояснений |
| `GEMINI_MODEL`            | нет         | Модель для сложных задач (по умолчанию `gemini-3.6-flash`)        |
| `GEMINI_MODEL_LITE`       | нет         | Модель для простых задач (`gemini-3.5-flash-lite`)               |
| `GEMINI_MODEL_FALLBACKS`  | нет         | Резервные модели при исчерпании квоты                           |
| `BLOB_READ_WRITE_TOKEN`   | нет         | Токен Vercel Blob; без него PDF хранятся на диске               |
| `LOCAL_UPLOADS_DIR`       | нет         | Каталог для PDF на диске                                         |
| `DEMO_PASSWORD`           | нет         | Пароль демо-учёток (`demo12345` по умолчанию)                   |

Квота Gemini Free Tier — 20 запросов в сутки на каждую модель, и модели делятся
на независимые «корзины»: кончилась квота у `gemini-3.6-flash` — у
`gemini-3.5-flash-lite` она ещё есть. Поэтому простые задачи идут на lite-модель,
а при 429 или 503 запрос переносится на следующую модель из
`GEMINI_MODEL_FALLBACKS`. Ответы кэшируются в Postgres на 24 часа.

Обратите внимание: `gemini-3.5-flash` и `gemini-3.6-flash` делят **одну** квоту —
запрос к `3.5-flash` отвечает бэкендом `3.6-flash`.

## Разработка

```bash
pnpm dev            # дев-сервер
pnpm build          # продакшен-сборка
pnpm test           # тесты (vitest)
pnpm lint           # ESLint
pnpm db:migrate     # новая миграция (создаёт файл в prisma/migrations)
pnpm db:studio      # Prisma Studio
```

Тесты покрывают чистые функции в `src/lib/`: нормализацию текста, разбор
фраз, ранжирование, выбор модели Gemini и форматирование дат. Они не требуют
БД и сети.

## API

Публичные, без авторизации: `POST /api/auth/login`, `POST /api/auth/logout`,
`POST /api/feedback`, `GET /api/health`, `GET /api/me`.

Остальные требуют сессии; права роли проверяются в каждом роуте:

| Метод                     | Путь                        | Назначение                                            |
| ------------------------- | --------------------------- | ----------------------------------------------------- |
| GET                       | `/api/projects`             | Реестр с фильтрами (`q`, `status`, `category`)        |
| POST                      | `/api/projects`             | Создать проект                                        |
| GET, PUT, DELETE          | `/api/projects/:id`         | Проект                                                |
| GET, POST, DELETE         | `/api/projects/:id/files`   | Файлы и ссылки проекта                                |
| GET, PUT, DELETE          | `/api/projects/:id/passport`| Паспорт ИИ-агента                                     |
| PATCH                     | `/api/projects/:id/publication` | Статус публикации                                 |
| POST                      | `/api/projects/:id/view`    | Счётчик просмотров                                    |
| GET                       | `/api/universities`, `/api/universities/:id` | Вузы                           |
| GET, POST                 | `/api/hearings`, `/api/hearings/:id` | Заслушивания                           |
| POST                      | `/api/ai-search`            | ИИ-поиск по описанию задачи                           |
| GET                       | `/api/export/dashboard`     | Выгрузка в XLSX                                       |
| POST                      | `/api/upload`               | Загрузка PDF (до 4 МБ)                                |
| POST                      | `/api/admin/import/projects`, `/api/admin/import/universities` | Импорт из Excel/CSV |
| POST                      | `/api/admin/reindex`        | Пересчёт направлений                                  |
| GET, POST, PATCH, DELETE  | `/api/admin/users`          | Пользователи                                          |
| GET                       | `/uploads/:filename`        | Отдача загруженного PDF                               |

## Устройство проекта

```
src/
├── app/                    # страницы и API-роуты (App Router)
│   ├── api/                # REST API
│   ├── admin/              # админ-панель
│   ├── fonts/              # шрифт Inter (latin + cyrillic)
│   ├── projects/ universities/ regions/ # витрина портала
│   └── ai-search/          # поиск по описанию задачи
├── components/             # React-компоненты по доменам
├── lib/
│   ├── search/             # движок поиска: text, taxonomy, classify, engine, store
│   ├── geminiSummary.ts    # пояснения модели поверх готовой выдачи
│   ├── gemini-models.ts    # выбор модели и фолбэк по квотным пулам
│   ├── llm-cache.ts        # кэш ответов модели в Postgres
│   ├── schemas.ts          # Zod-схемы тел запросов
│   ├── auth.ts             # сессии, роли, guard-функции
│   ├── uploads.ts          # хранение PDF (Blob или диск)
│   └── datetime.ts         # даты по казахстанскому времени
├── context/LangContext.tsx # переключение языка (ru/kz)
└── types/index.ts

prisma/
├── schema.prisma           # схема БД
├── migrations/             # миграции (migrate deploy)
├── seed.ts                 # регионы, технологии, администратор
└── seed-demo.ts            # демо-данные для локального стенда
```

Поиск разделён на два слоя: `src/lib/search/` считает выдачу (морфология,
таксономия из 20 направлений, ранжирование) и не зависит ни от БД, ни от
сети — поэтому его и покрывают тесты. Gemini отвечает только за человеческие
формулировки поверх уже готовой выдачи и не влияет на состав и порядок
результатов.

## Развёртывание

Основной путь — Docker Compose. Перед `docker compose up -d --build` на сервере:

1. Задайте в `.env` `POSTGRES_PASSWORD`, `ADMIN_PASSWORD` и `NEXT_PUBLIC_APP_URL`.
2. Настройте обратный прокси (nginx) с сертификатом и пробросом
   `X-Forwarded-For` — по нему работают лимиты входа и антиспам.
3. Если том с данными уже существует, смена `POSTGRES_PASSWORD` в `.env` не
   меняет пароль в самой БД. Смените его вручную:
   `ALTER USER postgres WITH PASSWORD 'новый';`
4. Задеплойте миграции: сервис `migrate` применяет их сам при старте.

На Vercel загруженные PDF хранятся в Vercel Blob — для этого нужен
`BLOB_READ_WRITE_TOKEN`. Без него приложение пишет PDF на диск.

Время и даты в портале показываются по казахстанскому стандартному времени
(`Asia/Qyzylorda`, UTC+5) независимо от часового пояса сервера.

## Безопасность

- Секреты живут только в `.env` (в `.gitignore`), в `.env.example` — плейсхолдеры.
- Настоящая проверка сессии и ролей — в каждом API-роуте и на страницах;
  middleware отвечает только за переадресацию неавторизованных на вход.
- Тела мутирующих запросов проверяются Zod-схемами: неверный enum даёт 400,
  а не 500.
- Ссылки на файлы ограничены схемой `http(s)://` или `/uploads/`, поэтому
  `javascript:`-ссылка не попадает в базу и не рендерится на странице.
- Загруженные PDF приватны: отдаются через `/uploads/:filename` с проверкой
  прав по проекту-владельцу, с заголовком `Cache-Control: private`.
- Лимит входа считается по email, а не по IP: заголовок `X-Forwarded-For`
  подделывается клиентом.
